# Fanout 排查手册（内部记录，2026-10-29，不对外发）

目标：下次再出问题，按这篇走，不重复犯今天的错。
红线：本篇只写路径、命令骨架、校验方法，不写密码、密钥、完整身份、完整订阅链接、邮箱。身份只比对 hash 前缀，订阅链接只记主机类型和测试结果，不贴完整链接。

## 一、动配置前必做（备份）

1. 备份两台的 fanout 四件套：`native.json`、`xray.json`、`state.json`、`settings.json`，放到带日期时间的备份目录。
2. 备份改动点的服务配置：改 nginx 改 nginx 的站点文件，改 Caddy 改 Caddyfile，改前各备份一份。
3. 备份完验 hash：改前、改后各记一次 hash 前缀，恢复时要能对上改前 hash 才算恢复成功。
4. 没备份不许重启、不许清隧道文件、不许删旧文件。2026-10-28 的根因就是无备份重启 + 清隧道文件。

## 二、重启后必查（只读，不许先猜原因）

1. 查面板入口：每台的入口是不是还在、是不是启用、绑的隧道 ID 是不是还在。
2. 查生成文件：`xray.json` 是生成的，不要手改它，改 `native.json` 后重启服务，看生成文件时间是不是刷新、身份是不是跟改后一致。
3. 查出口：每个节点单独测出口，区分直连出口和家宽出口，不要只看“通了”。
4. 查手机端：服务器侧通过两次也不算数，必须手机导入 + 手机测延迟，手机绿了才算通。2026-10-29 下午就是服务器通过、手机全红。

## 三、身份碰撞排查（两台机器同名不同出口）

1. 症状：手机上看到重复名字、或一台的节点在另一台上也出现、或改了一台另一台也跟着变。
2. 方法：分别读两台的 `xray.json`，只比对身份 hash 前缀（UUID 前缀、私钥前缀、短 ID 前缀、SNI），不要贴完整值。
3. 处置：先备份两台，再只改其中一台的身份，改完重启、验生成文件、验出口，另一台不动。改完把手机上旧的重复条目清干净，旧条目清不干净会一直误导。
4. 2026-10-29 实例：ARM 与 AMD 曾共用身份，ARM 改后只剩一个直连入口，AMD 家宽不变，手机上旧的已删入口要用户自己在客户端里删，服务端删不掉客户端旧条目。

## 四、干净节点集（2026-10-29 定版）

- 1 个直连 + 6 个家宽，一共 7 个。
- 排除：已删的直连重复入口、不安全的老协议入口、已停用的协议入口。
- 订阅内容要逐条对：身份是不是最新、协议是不是在用、节点是不是这 7 个，少一个、多一个、旧一个都不许发。

## 五、旧订阅复用排查

1. 先读旧订阅返回的内容：是面板生成的还是静态文件，是不是最新身份，是不是包含已停用协议，是不是缺新节点。
2. 旧订阅返回不稳定（一次 200、一次 403、一次不完整）时，不要反复刷旧链接，先查旧链接的源头是哪个服务、哪个配置，不要凭感觉复用。
3. 有一条对不上，就放弃复用，重新生成干净订阅，不要在旧链接上打补丁。

## 六、订阅链接生成与验收（下载口和节点流量分开）

1. 节点流量本身不走下载口中转，下载口只负责发一次节点列表，节点流量走直连 IP。
2. 下载口要求：中性主机名、随机长路径、HTTPS，禁止明文公网 IP 链接、禁止一看就懂的主机名、禁止长期固定路径。
3. 生成步骤：备份源站配置 → 在源站加随机路径、拷干净文件到源站 → 重载服务并验语法 → 从 agent VM 外部走真实下载路径实测（状态码、字节数、行数、节点数）→ 手机远程订阅刷新导入、手机测延迟。
4. 验收标准：服务器侧 200 不算数，必须手机导入后 7 个节点都出现、多数绿。2026-10-29 终验：手机上 7 个出现、6 绿 1 红，红的那个是隧道本身不稳，不是链接问题。
5. 失败排查：下载口返回通用 404 时，先直连源站 IP 加 Host 头测源站路径（源站通、下载口 404 = 中转源站不一致，不是缓存问题），再查源站日志里下载口请求是不是 0 次。不要反复换 token 掩盖源站不一致。
6. 用完处理：用户确认手机导入后，再决定是否删下载路径。没确认导入前不要删，确认后不要留长期路径。临时路径用完要清文件、清配置、重载、复测 404。

## 七、密码库三处互不同步（2026-10-29 纠正）

1. 三处：聊天工具的安全卡库、枢纽浏览器里的登录态、自托管密码库。互不同步，只在一处存过，另外两处不会自动有。
2. 官方云端账号和自托管账号是两个账号。官方页面上登不上自托管账号是正常的，不要在官方页面反复试。
3. 自托管排查：
   - 枢纽浏览器上，自托管页面在枢纽本地服务上能打开，不要用官方页面当自托管入口。
   - 新版本地软件的下拉里只有官方两个选项、没有自托管选项时，自托管不在那个下拉里，要去自托管自己的页面或在软件设置里设自定义服务器，不要在下拉里找。
   - 本地软件登不上、枢纽浏览器登得上时，先分清是本地还是枢纽：本地要先确认本地设备在不在内网、本地软件的服务器地址是不是改成了自托管，枢纽登上不代表本地能登上。
4. 以后密码只存枢纽和自托管库，聊天工具的安全卡不再作为新密码的存放处。已存在的安全卡条目只记网站名，不记账号名和密码值，不许从安全卡往枢纽倒数据。

## 八、CF 与主机名取舍

1. 节点流量不走 CF 前端，CF 只负责下载口那一次小流量，这是两回事，不要混成“节点走 CF”。
2. 中性主机名是定好的方向，临时主机、旧主机、明文 IP 都不许当正式下载口发出去。
3. 新主机名要改 DNS 时，只能走枢纽上已登录的会话，不要让用户重新登录、不要在聊天里讨论账号细节。
