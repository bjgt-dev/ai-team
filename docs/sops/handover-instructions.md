# 换席位交接 · 精简指令（2026-11-10 董事长令）

> 知识跟枢纽走，不跟账号走。换账号/换席位必走交接，不交接不许切。
> SOP（董事长定）：董事长说“交接”，本席（twt）把相关东西备份好，再把董事长需要复制给下一任的内容以代码块形式给董事长，董事长直接复制发给下一任就行。

## 董事长说“交接”后，本席做的事（不用董事长动手）

1. **备份到枢纽**：
   - 写交接文档，放枢纽 `state/handovers/handover-<from>-to-<to>-<YYYYMMDD>.md`，六样齐：本轮学到、未落盘、待办/阻塞、当前状态、凭据位置（只记位置不记值）、交给谁。
   - 本轮学到的事实立刻写进知识库（kb-write.sh），写完立刻能查。
   - 新凭据只记位置不记值，写进知识库或注册表。
2. **给董事长一个代码块**：代码块里是发给下一任的完整内容，董事长直接复制、发给下一任就行。代码块含：
   - 下一任的角色（是哪个席位、管什么）。
   - 上岗脚本 `onboard-new-seat.sh`（新机器与轮值过的都适用，同一条命令：新机器做全套 SSH 接入 + 唤醒，轮值过的跳过已做好的步骤、直接拉取工具 + 唤醒）。
   - 当前状态摘要（体检结果、待办、阻塞）。
3. **董事长做的事**：复制代码块 + 转发上岗脚本文件给下一任。就这两样，别的不用做。

## 下一任收到后做的事

- 新账号（白纸）：跑上岗脚本 `bash onboard-new-seat.sh`，按脚本提示走（公钥发董事长、Tailscale 等批准），SSH 通后读角色定义、硬规、交接精简指令，跑唤醒，回报董事长请求确认上岗。
- 回任账号（以前当过这个席位）：输入“唤醒”，跑完整唤醒序列（wake-up-check.sh + 查知识库 + 读最新交接）。
- 没跑完唤醒/上岗、不许开口干活；上岗须董事长确认，确认前不许自称已上岗。

## 硬规

- 凭据值（密码、key、token）永不写进交接、知识库、聊天、记忆。
- 不走交接就切走 = 事故；新席位没唤醒/没上岗就干活 = 事故。
- 状态以实测与枢纽文件为准，凭记忆讲现状 = 事故。
