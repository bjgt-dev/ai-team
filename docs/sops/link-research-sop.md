# 链接深挖 SOP：从一条链接到可用的方法论

**董事长定，2026-11-06。** 适用：董事长发来的链接、本席在情报管线里发现的好链接。目标：一条链接不只看完就忘，要顺着专题挖深、提炼成方法论、实践验证、MVP、再迭代。

## 流程（董事长原思路）

1. **收**：链接进登记表（状态：待验），记来源、日期、为什么值得看。
2. **挖**：顺着专题深入，多角度、多信息源搜集，不只看原文——看作者其他东西、看实现、看别人怎么评价、看数据。
3. **炼**：提炼成方法论，写成 SKILL.md 契约 + 检查清单 + 验收标准，配一个最小可跑的例子。
4. **验**：实践验证。先 MVP（最小闭环跑通），再接真实管线跑一轮。
5. **迭**：复盘一次（什么有效、什么要改），再决定下一轮改什么，状态更新回登记表。

## 补充（本席加的，董事长已同意方向）

- **先筛后挖**：不是每条链接都值得深挖。先过一筛——跟三条商业线或基础设施有没有关系、是不是高星验证过（只认 GitHub API 实查数，不认网文转载数）、是不是一手来源。不值得的只记一句话，不启动深挖。
- **三角验证**：同一结论至少两个独立来源印证；星数、更新时间、许可证、实际跑通四项必查。
- **时间盒**：深挖设 1 小时时间盒，超时先报进度，不闷头挖。
- **验收先定**：验证开始前先写死“什么叫跑通了”（退出码、数字、文件证据），不凭感觉说通过。
- **失败也记**：验证失败要写清失败原因和边界条件，失败记录本身就是成果，不算白干。
- **审核分层**：方法论产出过五层审核（结构、事实、内容、风格、可执行），见 local-harness-method。
- **状态不丢**：每条链接在登记表里只有三种终态——已验（附证据路径）、不做（附原因）、待验（附下次动作和期限）。没有第四种。

## 落盘位置

- 登记表：枢纽 `~/ai-team/state/skills-registry.md`（技能类）与免费渠道总表（模型类）；本地镜像在 `~/workspace/goals/ai-4/hidden_files/`。
- 方法论产出：`~/workspace/custom-skills/local-<名字>/SKILL.md`。
- 验证证据：对应技能目录下的 `runs/<日期>/report.md`。
