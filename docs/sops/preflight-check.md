# 开工前强制预检门：先找公开资源，不手搓

**董事长令，2026-11-06。硬规，违反即算事故。**

## 规则

任何新活开工前（派 subagent、建任务、写脚本、装技能、改管线），必须先过这道门，不过不许动手。

## 四问（逐项回答，写进任务简报或台账，不许只在心里过）

1. **搜了没有？** 公开资源搜了哪些地方（GitHub 关键词、技能登记表、情报管线、SOP 看板），关键词是什么。
2. **找到了什么？** 逐条列：名字、星数（只认 API 实查）、许可证、能不能直接用。
3. **用还是造？** 能直接用的直接用；能改改用的改改用；只有确实没有、或现有方案验证过不适用，才能自己造。自己造必须写清“为什么现有的不行”，附证据（跑过、读过、星数不够），不许写“没找到”。
4. **验证计划是什么？** 采用的东西怎么验证（跑通标准、对照实测），造的东西验收标准是什么。

## 决策表

| 情况 | 动作 |
|---|---|
| 有高星现成方案，能直接用 | 直接用，不许重造 |
| 有现成方案，需小改 | 改改用，改动记进登记表 |
| 只有低星方案（<1,000★） | 按选品规则直接略过，视为没有 |
| 确实没有，或现成方案已验证不适用 | 自己造，验收标准先定 |

## 机制（不是口头承诺）

- 台账：每次预检记一条 `~/workspace/tools/preflight-ledger.jsonl`（任务、搜了哪、找到啥、决策、时间），用 `~/workspace/tools/preflight.sh` 记。
- 派活时：subagent 简报第一段必须贴预检四问的答案，没贴的活不许派。
- 复核：晨报复核三指标里加一项“无预检开工”，目标 0；同一任务第二次无预检开工，按事故计。
- 例外：董事长明确说“直接做”的，才可以跳过预检，但要在台账里记“董事长直接做”。
