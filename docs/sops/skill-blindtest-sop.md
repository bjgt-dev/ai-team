# Skill 季度盲测 SOP（Thorsten Ball Rule 6，2026-11-07）

**目的**：skill 和 AGENTS.md 越攒越多，从没盲测过到底有没有用。本 SOP 每季度一次盲测，拿数据说话：没效果的指引删掉或重写，有效果的留下来写进知识库。

## 一、盲测流程

1. **挑任务**：挑一个文档声称能让它变容易的任务（如“按约定加一个新 API 端点”“按合同模板派一个新任务”）。任务须具体、可重复、有明确完成标准。
2. **对照组**：把知识文件（skill / AGENTS.md 相关段）拿掉，跑 3 次。记录每次：是否遵守约定、完成时间、token 数、出错次数。
3. **实验组**：带着知识文件，跑 3 次。记录同样四项。
4. **对比**：实验组有没有更遵守约定、更快完成、更少 token？
5. **处置**：没效果的指引删掉或重写；有效果的留下来，写进知识库（写清解决了什么、验证数字、以后什么活优先用它）。

## 二、报告格式

每季度一份盲测报告，写清：
- 任务与完成标准。
- 对照组 3 次数据（遵守约定 Y/N、时间、token、出错）。
- 实验组 3 次数据（同上）。
- 结论：有效 / 无效 / 部分有效。
- 删了哪条指引、留了哪条、改了哪条（附文件路径与行号）。

报告落盘：`~/ai-team/state/skill-blindtest-<YYYY>q<N>-REPORT.md`，同时登记进资产库。

## 三、执行方

- trial 须调模型：走枢纽网关（worker-1 无模型、无网关 token，跑不了 trial）。
- worker-1 只负责按本 SOP 跑对照脚本、收数据、写报告；trial 本身由枢纽 handler 接手。
- 首轮（2026 年 Q4）在 11 月底前完成，任务号 `skill-blindtest-2026q4`。

## 四、周期

- 每季度一次（Q1/Q2/Q3/Q4），季度末最后一周执行。
- 连续两季度同一指引无效 → 直接删除，不再重测。
