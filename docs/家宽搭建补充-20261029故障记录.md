# 家宽搭建补充：迁移后翻车的那几件事（2026-10-29）

这篇是补充，不是重写搭建教程。只记今天迁移后真实翻过的地方，下次照着避坑。

## 1. 迁移前先备份，没备份就别重启

迁移重启前，没有先把配置文件和面板状态完整备份，重启后隧道被清掉，六个家宽入口也没自动恢复。
教训就一句话：先备份，再重启，备份要验过能读、能恢复才算数。重启后第一件事不是报“好了”，是逐个对：入口还在不在、出口还是不是家宽。

## 2. 服务器上通了，不等于手机上通了

今天有两次，服务器上测试都通过了，手机上还是全红。
以后验收只认手机端：手机上导入、手机上测延迟、手机上绿了才算通。服务器侧通过只是中间态，不是结论。
还有一次更早的教训：只在面板上重建、绑好就说“能用”，没做手机验证，结果第二天全是问题。面板上看着对，不等于手机上能用。

## 3. 两台机器用了同一套身份，手机上会看到重复节点

两台机器上的节点用了同一套身份信息，手机上看起来像重复的节点，实际出口完全不同，一台是直连，一台是家宽。
改身份之前先备份两台的配置，改完只改的那台要立即验，另一台不要动。改完还要把手机上旧的重复条目清干净，不然旧条目会一直误导排查。
以后新增节点，先查身份是不是已经在别的机器上用过，撞了就换新的，不要复用。

## 4. 旧订阅别急着复用

旧订阅里的内容可能还是旧身份，可能还带着已经停用的老协议，还可能少了新加的节点、多了一台已经删掉的节点。
复用旧订阅之前，先逐条对：身份是不是最新的、协议是不是还在用的、节点是不是现在这套干净的节点。有一条对不上，就不要复用旧链接，重新生成干净的订阅。

## 5. 订阅链接别图省事

节点本身的流量是加密的，但订阅链接只是个下载口，下载口本身也要安全。
不要用明文地址，不要用一看就懂的名字，不要用长期不变的固定路径。下载口要用中性名字、随机长路径，用完确认导入后就删掉。节点流量本身不走这个下载口的中转，下载口只负责把节点列表发到手机上一次。

## 6. 密码别存在聊天工具那边，存到自己的库里

聊天工具里填过的安全卡、浏览器里的登录态、自托管的密码库，是三个地方，互不同步。
只在聊天工具里存过，自己的库里不会自动有；只在官方云端有账号，自托管那边也不会自动有。官方页面上登不上自托管账号是正常的，要去自托管自己的页面登，不要在官方页面上反复试。
以后密码只存到自己的枢纽和自托管库里一次，之后就不用每次都重新输入。登录态过期、网站要验证码的时候，还是要自己动手一次，这是正常的，不是库坏了。

## 7. 今天最后的结果

干净的一套是：一台直连加六个家宽，一共七个。手机上导入后，六个绿，一个红。
红的那个是它自己的隧道不稳，不是订阅链接的问题，先用绿的那六个，红的那个以后再单独查隧道，不要为了它把整套推倒重来。

## 下次必做清单

1. 动配置前先备份，备份验过再动。
2. 动完先在服务器上验，再在手机上验，手机绿了才算完。
3. 身份、订阅、下载口，三样逐条对，不要凭感觉复用旧的。
4. 密码只存自己的库，三个库互不同步这件事要记牢。
5. 出问题先记下来，记到这篇补充里，下次不重复犯。
