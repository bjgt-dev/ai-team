# 情报增量扫 Harness：多层审核节点（每层清单）

本轮不只“跑通了就行”。五层按下面开；通过的层不重审，失败的层只修最小切片。

## L1 结构层（脚本审，`check-run.py`，每轮必开）

- [ ] `result.json` 能解析，`mode == "incremental"`（过载判 DEFERRED，不算 FAIL）
- [ ] `sources` 含 7 个源（含 `技能`）；缺源要在 `check.json` 里列出，不许当没发生
- [ ] `new`、`skill_new`、`free_hits`、`skills_appended` 四数非负
- [ ] `new > 0` 时增量记录行数增长且有本轮 `## HH:MM 增量` 小节
- [ ] `skills_appended == 登记表第七节实际增加行数`
- [ ] `free_hits > 0` 当且仅当本轮新增报警文件

## L2 事实层（主 Agent 内联核对，写报告前打勾）

- [ ] 报告里的每个数字都能在 `result.json` / `meta.json` / `record-tail.txt` 里找到
      （本轮 new、skill_new、free_hits、登记表行数、报警文件数——逐个能指出来源）
- [ ] “已完成”只写有证据的：登记写了几行、报警写了几个文件，写清路径，不写“已处理”
- [ ] 源失败的说法与 `collect.err` / `result-full.txt` 一致（X 缺 cookie、Linux Do 403，
      写清是哪一轮、什么错误，不编原因）
- [ ] 不确定的写“未核实”：例如某源返回 0 条时，写“本轮 0 条（原因未核实）”，不写“该源已死”

## L3 内容层（主 Agent 内联，按 triage-guide 逐条）

- [ ] 本轮每个新条目都有去向：免费命中定性四档（SOP / 已有 / 非模型 / 假命中），
      技能命中定性三档（登记 / 待验 / 不登），没有“没提就是没做”的项
- [ ] SOP 项只记待办，不直接加网关（加网关是另一个 Harness 的事）
- [ ] 边界守住了：没改生产脚本、没动去重状态、没删报警文件
- [ ] 失败项有下一步：X 登录缺用户名（等浏览器任务 + 正确用户名）、Linux Do 403（连续两轮才升级）

## L4 风格层（写 report.md 前打勾，30 秒）

- [ ] 结论先行，`report.md` 结论段 ≤300 字
- [ ] 输出脱名：只称角色，不写真实姓名
- [ ] 只报结论、阻塞、下一步三段；不贴过程、不贴脚本、不贴原始日志全文
- [ ] 数字与结论一致（报告说“0 条新内容”，`result.json` 里 `new` 就是 0）

## L5 可执行层（脚本审，每轮必开）

- [ ] `run-incremental.sh` 退出码 0（SSH 失败、取证失败即 FAIL）
- [ ] `check-run.py` 退出码 0（verdict PASS）
- [ ] 同样输入重跑结果一致（seen 状态已写盘，重跑 new=0 是正常的幂等表现，不是失败）
- [ ] 回滚能用：生产脚本备份存在（`intel_pipeline.py.bak-20261106-skills`），
      登记表与增量记录只追加不覆盖

## 终审（本 Harness 不设独立终审，改为抽查）

- 常规轮次不设独立复核：L1 + L5 机器层全量 + L2–L4 内联清单。
- 每周抽查 5% 的轮次：由未参与本轮的 Agent 按本文件重验一遍（只看 `runs/<RUN_ID>/` 与枢纽 state，
  不重跑生产），抽查结论写进该轮 `report.md` 末尾。
- 抽查发现任一层失效（如连续 20 轮零 FAIL），把抽查提到 100% 直到连续 3 轮全绿。

## 失败回滚表

| 失败层 | 回滚动作 | 重做范围 |
|---|---|---|
| L1 / L5 | 停在当前 Phase，不进下一 Phase | 只修失败项（脚本 bug、取证缺失），重跑该层验收；不重跑生产采集 |
| L2 | 撤回报告里的相关数字，标“未核实” | 只改报告，不动产物 |
| L3 | 未定性条目补定性；越界动作停手 | 只补缺项 |
| L4 | 重写 report.md | 只重写，不重做 |
| 同一层连续两次 FAIL | 停下报父级，不许第三次硬试 | — |
