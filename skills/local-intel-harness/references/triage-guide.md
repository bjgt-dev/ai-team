# 分流复核指南（Phase 2：Agent 判断点）

采集与去重是脚本做的；下面两类判断必须由 Agent 逐条做，**每条都要在 report.md 里留一句结论**。
不判断、不留结论就进下一 Phase = 违规。

## 免费命中（free_hits）复核

每条命中先问三问，答完再定性：

1. **真免费吗？** 点进来源确认：免费额度 / 免费 Key / 免费试用三者要分清；“免费试用 7 天后自动扣费”
   不是免费；“注册送 $5 体验金但要绑卡”不是免费。
2. **是模型/渠道吗？** 银行开户奖励、论坛抽奖、客户端内额度（转不成 API Key 的，如 ZCode 5 亿 token）
   记“非模型”，不进 SOP。
3. **我们有了吗？** 查网关渠道表与免费渠道总表，已有的记“已有”，不重复报。

定性四档（只能取其一）：

| 结论 | 含义 | 下一步 |
|---|---|---|
| `SOP` | 真免费模型/渠道，且我们还没有 | 进羊毛 SOP：核实 Key → 加网关 → 入总表（走 local-free-channel-harness） |
| `已有` | 我们已有该渠道/模型 | 不动，只在报告里记一笔 |
| `非模型` | 不是模型/渠道（如银行奖励、抽奖、客户端内额度） | 不动，记原因 |
| `假命中` | 关键词误触（如“免费”出现在无关上下文） | 不动，记原因；连续假命中要修关键词 |

## 技能命中（skill_new）复核

每条先问两问：

1. **真技能吗？** `[SKILL.md 已确认]` 是脚本探过的（仓库根有 SKILL.md 或 skills/ 目录）；
   `[SKILL.md 未确认]` 与 `[种子跟踪]` 不要直接当技能——前者只说明搜索命中了关键词，
   后者只是种子仓库的星数快照。
2. **值得登记吗？** 对照 `local-harness-method` 的审核三问：真技能、免费、要不要付费 API；
   不过审的记原因，不进登记表（脚本只自动追加“已确认”的，复核要把关）。

定性三档：`登记`（已进登记表第七节，核对无误）/ `待验`（需人工再看一次，如 awesome-list 里的混合仓库）/
`不登`（不是技能或要付费，记原因）。

## 源失败复核

`check.json` 的 `source_failures` 逐条定性：

| 源 | 常见失败 | 定性 |
|---|---|---|
| Linux Do 403 | Cloudflare 拦 Playwright 之外的请求，或登录态过期 | 若连续两轮 403，记 BLOCKED 并报父级（不要自己改登录） |
| X 缺 cookie | `x-cookies.json` 缺失/过期 | 记 BLOCKED；登录要浏览器任务 + 正确的用户名，**不要猜用户名再试**（会触发限流） |
| YouTube / GitHub 超时 | 偶发网络抖动 | 单轮失败记“偶发”，连续两轮失败才记 BLOCKED |
| 技能源 GitHub 限流 | 未登录 60 次/小时 | 记“限流”，下一轮自动恢复；不要加 Key 绕过去（Key 要走正规渠道） |
