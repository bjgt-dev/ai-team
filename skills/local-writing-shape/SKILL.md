# Shape raw material into an article

## Read the pile and settle prerequisites

- Read the raw material file end to end before you do anything else.

- Treat the pile as a quarry to mine, not a script to follow.

- Do not edit the raw material file.

- If the user did not say where to save the article, ask once and remember the path.

- Settle with the user what the reader already knows walking in.

## Shape it paragraph by paragraph

- Draft 2 to 3 candidate openings and show all of them to the user.

- Make each opening imply a different thesis or angle for the article.

- Let the user pick one opening or compose a hybrid from them.

- Grow the article one agreed paragraph or block at a time after the opening lands.

- Ask what the reader needs to hear next given the opening, then pull material from the pile to answer it.

- Argue each format choice out loud with the user, using prose for argument, lists for parallel items, callouts only for asides that would derail the main argument, tables only when the same shape repeats 3 or more times, quotes only when the original wording is the point, and code blocks for multi-line runnable or illustrative code.

- Push back on weak transitions and cut any paragraph that does not earn its place.

- Name a gap explicitly when the pile lacks something the article needs, and ask the user to supply it or cut that section.

- Do not publish the article, format it for a specific platform, or add frontmatter the user did not ask for.

## Run it as a journey of beats when the user wants that shape

- Offer 2 to 3 candidate starting beats drawn from the raw material, each a different entry point into the article.

- Note what new concepts each candidate beat grounds, and let the user pick one.

- Write only the picked beat to the article file, then stop there.

- Re-read the article file from disk, then offer 2 to 3 candidate next beats from where the article now stands.

- Keep each beat to one move, whether that move is one sentence, one paragraph, or a short vignette.

- Split a beat that needs five paragraphs and three subheadings into two beats.

- End the journey when it is complete, even if the pile still has leftover fragments.

## Ground each concept before you use it

- Keep a running list of what is grounded so far and update it each time a beat or block lands.

- Treat a concept as grounded only when the reader brought it in or an earlier beat or block established it.

- Ground the idea and the term together when a concept has a name.

- Offer only beats or blocks that are reachable from the current grounded set.

- Add a grounding beat or block first when a tempting move needs a concept nothing has grounded yet, or promote that concept to a prerequisite.

## Append as you go and finish on the reader

- Append to the article file as each beat or block is agreed, and never write ahead.

- Re-read the article file from disk before every write and preserve user edits absolutely.

- Edit only the specific beat or paragraph the user asks to rewrite, and leave the rest alone.

- Let the user decide when the article is done.
