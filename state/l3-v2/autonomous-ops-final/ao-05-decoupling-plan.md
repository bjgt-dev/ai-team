# 05 后台与会话解耦验证方案（草稿，待 SSH 恢复后存入 autonomous-ops-final）

目标：证明后台运行不依赖浏览器、董事长聊天、Muse 席位空闲、幕僚长活动会话、单个 LLM 长任务。

## 已有解耦证据（不需新造）
- Supervisor、butler-loop、seat_revive、agent-executor、five-step 均由 systemd/cron 驱动，与 Muse 对话会话无关；2026-11-02 全天 cron 日志可查。
- 席位锁机制本身证明：巡航会话占锁时外部任务只能等待，说明执行不在对话会话内。

## 待跑验证（测试 1 与测试 5 的具体步骤）
1. 建立低风险后台任务：确定性 hub-local 任务（写时间戳文件 + 队列状态推进），进入持久化 queue.json，任务编号与时间记录在案。
2. 停止一切人工干预：不再由 Muse 对话发送任务命令，等待至少两个 Supervisor 周期（10 分钟）与一次 cron 执行窗口。
3. 由 cron 侧独立完成：Supervisor 回收/推进状态、执行脚本写回执、归档脚本写入知识资产、仪表板更新。
4. 重新打开对话检索：按任务编号查 queue.json、回执、归档、仪表板四处，缺一即 FAIL。
5. LLM 不可用分支：同一任务在席位脑 DEAD（当前 Zen 状态即天然条件）下，确定性部分仍完成；依赖语义判断的部分进入等待队列并留 note，不得丢任务、不得假 DONE。
6. 长会话不持锁分支：验证短锁架构实施后，长 LLM 会话不再持有全局调度锁（待第一批实施后复测，实施前记 NOT TESTED，不得冒充）。

## 判定标准
- 四处证据齐全且时间戳在“无人工干预窗口”内，测试 1 通过；任一缺失即 FAIL。
- 本方案为测试设计，不改生产代码；短锁相关复测须待第一批定案实施后。
